# Retake contracts

Retake edits dialogue in existing scenes while retaining the original faces, source performances and room sound. Marc selected the product name, amplifier-smart-tool-retake repository and voice/mouth-only first scope. Face swap is deferred.

The detailed promises below are draft proposals. They define the intended smart-tool layer and its connections; the existing JSON runner implements only part of that experience. Product naming/private-repository setup does not turn every draft behavior into accepted or delivered functionality.

- [Scene editing and caller interaction](scene-editing.md) covers requests, Outtake discovery, automatic preparation, source performance, protected sound and correct visible mouths.
- [Runtime capabilities](runtime-capabilities.md) covers local environment profiles, separate reasoning/generation providers, backend readiness and remote-worker boundaries.
- [Execution and delivery](execution-and-delivery.md) covers durable jobs/revisions, retry/recovery, evidence, comparisons and usable delivery.

Marc owns product direction. The local implementation owns Ducasse integration within assigned scope. The other agent retains Spark administration. Exact schemas, automatic preparation mechanisms, agent-facing transport and backend protocols remain open where the contracts say so. Routine reversible implementation choices within an assignment need no new sign-off.

The intended experience is in [the vision](../docs/VISION.md). Current work, accepted direction, proposals and evidence are distinguished in [the work record](../docs/WORK-RECORD.md). Shared promises have one home here; setup guides and checks link them rather than silently adding requirements.
